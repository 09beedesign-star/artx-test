## Working Notes

- Follow `AGENTS.md` for ArtX test release workflow before any test environment publishing.
- Model selector product rule: user-facing model selectors should only expose the current product-level models `GPT 大语言模型`, `Image Two`, and `Nano Banana`; do not show unused variants such as `Nano Banana lite` or internal GPT version names in selectors.
- Log lookup rule: when the user says "查看日志" in this workspace, read `docs/dev-log.md` by default.
- Development log rule: when the user says "添加日志", "记一下日志", or asks to log a task, append the record to `docs/dev-log.md` using the established template; AI-related records must include `generationId`, `backendTaskId`, and `providerTaskId` or explicitly mark missing IDs as `N/A`.
- Credential values are not stored here; only credential locations may be recorded if needed.
- Product model: users pay for compute, compute is converted into platform credits/points, and admin tooling should track feedback, payments, accounts, and quota/credit operations.
- Admin prototype should include a top-right notification center for urgent operations such as payment exceptions, runtime errors, integration latency, and credit/risk events.
- Admin backend is connected at `/admin-prototype`, but it must not be exposed in the main website navigation; production access should use an independent admin subdomain such as `admin.*` or `VITE_ADMIN_HOST`.
- Formal admin access uses role-based permissions: ordinary users are `viewer`, default `09bee` is `super_admin`, and admin routes require `admin:access` instead of only checking login.
- Admin data integration rule: `/api/admin/*` now uses `server/admin-store.ts` as the MVP operating data source for users, orders, credits, AI tasks, providers, feedback, alerts, risk events, audit logs, and plans; all write operations must append audit logs and must never expose credential values.
- Billing integration rule: membership purchase is no longer only a local UI mock; `/api/billing/summary`, `/api/billing/orders`, and `/api/billing/orders/:orderId/pay` now create server-side orders, confirm payment, issue credits into the admin ledger, and keep `/admin-prototype` overview/orders/credits aligned with the same source of truth.
- Billing success feedback rule: subscription and recharge payment completion should return to an in-site success confirmation modal, not only a toast; the modal uses the prompt-send green `#C5ED47` as the top status bar and button color, shows the subscribed package or recharge amount/credits, and requires an explicit confirmation button.
- Global toast alignment rule: bottom-centered Sonner toast defaults to the former expanded size, about 360px wide and 60px tall; text is centered when the full message fits within the toast content width, and switches to left-aligned two-line display when the measured text exceeds that width.
- Global toast negative state rule: bottom Sonner toasts whose type is `error` or whose title/description contains failure, error, unavailable, invalid, timeout, unable-to-connect, or equivalent Chinese negative wording should be marked as negative globally, show a leading `!`, use a deep red 30% transparent background, and keep prompt text white.
- Billing page layout rule: subscription and recharge cards must keep fixed dimensions across hover/click/selected states; the three visible subscription plans remain clickable as `Lite 入门版`, `Pro 专业版`, and `Studio 工作室版` rather than falling back to `当前不可用` based on current-plan level mapping.
- Billing subscription status rule: the billing page must derive the top-right current plan, subscription status, and current-plan disabled button from one `/api/billing/summary.plan` display state; `Free`, `Starter`, `Demo`, and recharge-only values are not active subscriptions and should show `未订阅`, while subscribed visible plans disable their own card button with `您已订阅该套餐。`.
- Billing upgrade-only rule: subscribed users can only move to a higher visible subscription tier; lower-tier/downgrade subscription cards must keep fixed layout but disable their button and show downgrade-unavailable copy.
- Billing price source rule: subscription prices and credits must match the real Wallyt QR/order amount; current membership credit rule is HKD 1 = 13 credits. Visible plans are Lite 19/51/174, Pro 89/240/817, Studio 139/375/1276 for monthly/quarterly/annual. Hidden backend-recognized plans are Creator 179/483/1643 and Business 1599/4317/14679. Do not reintroduce the old high display prices 109/499/929 or monthly-credit based bonus calculations.
- Wallyt payment rule: 威富通支付 is integrated through backend-only env vars `WALLYT_DOMAIN_URL`, `WALLYT_MCH_ID`, `WALLYT_SIGNATURE_KEY`, `WALLYT_NOTIFY_URL`, and optional `WALLYT_WX_APP_ID`; never commit merchant secret values, and verify callbacks through `/api/billing/wallyt/callback` before marking admin-store billing orders paid.
- Wallyt reconciliation rule: 威富通 XML 解析、下单签名、回调验签、主动查询、异常订单事件、右上角支付告警和专项回归测试统一由 `server/wallyt-payment.ts`, `server/index.ts`, `server/admin-store.ts`, and `scripts/verify-wallyt-payment.mjs` 覆盖；本地 `.env` 可加载真实商户配置但不要提交。
- Admin order reconciliation rule: `/api/admin/orders/:orderId` returns order detail with payment events, credit ledger entries, notes, refund events, feedback, audit entries, and a reconciliation timeline; admin order actions include notes, confirmed manual reissue, and confirmed refund with credit clawback.
- Admin refund flow rule: refund events include money-flow nodes for request, credit clawback, provider refund submission, provider processing, and user funds arrival; the current refund step is visible in the order detail panel and regression-tested in `pnpm verify:admin`.
- AI billing policy rule: AI usage billing is controlled by the editable admin policy table saved through `/api/admin/ai-billing-policies/save`; successful AI tasks use the saved capability policy plus the user's membership discount, then write AI task records and credit ledger deductions. Cost/margin reports are estimated platform cost, not real provider invoice reconciliation.
- AI billing coverage rule: server AI usage accounting now covers text/image generation, background removal, HD enhancement, watermark removal, smart background, OCR, image edit, object erasure, image expansion, and generic `/api/ai/orchestrate`; failed authenticated tasks write admin alerts without deducting credits.
- Admin production-readiness rule: `server/admin-store.ts` now uses an `AdminDataRepository` boundary with JSON as the MVP adapter and `ARTX_ADMIN_DATA_BACKEND=json`; `docs/admin-database-schema.md` defines the target Postgres schema, and `pnpm verify:admin` runs the admin regression checks against a temporary data directory.
- Admin production-security rule: auth now enforces session expiry, login failure lockout, last-super-admin protection, self-disable protection, and high-risk admin write confirmations for AI billing policy changes and large credit adjustments; `pnpm verify:admin` includes these regression checks.
- Canvas persistence rule: real user projects use `canvas-*` IDs and must keep the latest edited nodes/edges in local storage; non-real test canvas states can be reset without touching user projects.
- Image generation recovery rule: text-to-image tasks with a `generationId` are also started on the backend `/api/images/tasks` background endpoint, so closing the browser can still recover completed or failed results when the user returns.
- Canvas assistant composer rule: image reference chips and annotation reference chips are ordered prompt segments; drag reordering must preserve the same order in both displayed prompt text and the reference image array sent to AI.
- Eraser AI rule: canvas eraser strokes call PicWish/佐糖 image object removal through `server/image-generation.ts#eraseWithPicWish`, using the official remove-objects `POST /api/tasks/visual/watermark` and `GET /api/tasks/visual/watermark/{task_id}` flow. It supports `sync=0` and `sync=1`, `image_file` or `image_url`, `mask_file` or `mask_url` or `rectangles`, provider task ID tracing, frontend transparent-hole masks, and white-remove/black-protect masks matching PicWish masked removal.
- Eraser isolation rule: the eraser path must not use local blur fallback, old masked compositing, or old result-guessing heuristics. If PicWish inpaint fails or returns no image, surface the failure instead of fabricating a blurred result; do not change outpaint, annotation, smart background, HD, layer editing, watermark, or background-removal paths when tuning eraser.
- PicWish logging rule: all PicWish/佐糖 calls must log server-side `[picwish]` JSON events for request, created task, polling, success, failure, and result download. Logs may include task type, endpoint, taskId, state, progress, duration, dimensions, and errors, but must never include API key values.
- PicWish response ID rule: all successful PicWish/佐糖 image capabilities must include provider task IDs in API responses as `providerTaskId` and, when multiple PicWish tasks are involved, `providerTaskIds`, so browser-side verification and `docs/dev-log.md` can trace each call without relying only on Render logs.
- Watermark removal rule: the image toolbar `去水印` command calls `client/src/lib/ai.ts#removeImageWatermark`, `POST /api/images/remove-watermark`, and PicWish/佐糖 `watermark` visual task; it must stay separate from eraser `inpaint`.
- Gemini image model rule: selectable Gemini/Nano Banana image models are exposed through `IMAGE_AI_MODELS` and routed as chat-compatible image models in `server/image-generation.ts`, so they avoid the unsupported Images API path.
- BKEEL image generation rule: `https://token.bkeel.com/v1/images/generations` returns an async `task_id`; image generation must poll the task result instead of expecting a synchronous `data[0].b64_json` response.
- Font design dialog layout rule: the panel must sit horizontally centered under the top canvas toolbar with 16px visual spacing, avoid horizontal scrolling, keep all style category labels/descriptions visible, keep every category preview image visible as a real proportional card instead of thin strips, and fit common browser heights with vertical-only internal scrolling.
- AI client routing rule: GitHub Pages builds must never send AI requests back to the Pages frontend; `client/src/lib/ai.ts` falls back to `https://artx-test.onrender.com`, and text-to-image requests with `generationId` should fall back to direct orchestration if the background task endpoint returns HTML/non-JSON.
- Smart background dialog layout rule: the panel must sit horizontally centered under the top canvas toolbar with 16px visual spacing, may use a wider content-led width, must keep upload, style, prompt, ratio, resolution, custom size, cancel, and create controls visible through vertical-only internal scrolling, and must not overflow the browser viewport.
- Smart background output rule: when product image, background reference image, prompt, ratio, and resolution/custom size are provided together, the reference image is only a style/lighting/material/background guide; the prompt still controls the specific requirements, and the returned bitmap must be normalized to the selected output size/aspect ratio with no black bars or empty gutters.
- Smart background canvas rule: when a user uploads both a product image and a background reference image, clicking create must place both source images onto the canvas before generation, then generate the result beside them; the API request must pass explicit output `customWidth/customHeight` derived from the selected ratio and 2K/4K/custom size.
- AI capability safety rule: before adding a new AI capability, if the implementation may touch or regress already tuned AI capabilities such as annotation, outpaint/expand image, smart background, eraser, background removal, HD, watermark removal, layer editing, or image editing, warn the user first with the affected capability list and regression risk before changing those paths.
- Quick image edit rule: the image node quick edit / smart edit flow must call `editImageWithPrompt` with the selected/latest image as the target canvas, preserving subject identity, pose, silhouette, composition, aspect ratio, and unmentioned regions; it must not call pure `generateAiImages` for local edits because that can regenerate a similar but different person/object and break later background removal.
- AI image regenerate rule: AI-generated image nodes expose a 60px green hover button labeled `再次生成`; successful nodes rerun into a new nearby image node, while failed nodes retry in place using the original prompt/model/ratio metadata.
- Canvas download/export rule: selected-image download, batch download, and artboard export must read remote images through a Blob/proxy fallback before drawing to canvas, otherwise cross-origin sources can make download/export fail or silently skip layers.
- AI expansion rule: `/api/images/expand` must use PicWish/佐糖 `POST /api/tasks/visual/advanced-image-expand` and `GET /api/tasks/visual/advanced-image-expand/{task_id}` through a dedicated expansion path, not the eraser/inpaint path; frontend expansion should send the enlarged canvas with transparent blank extension pixels plus a same-size mask, and returned expansion results must include provider task IDs before writing back to canvas.
- Multi-platform cover rule: the canvas multi-platform cover panel stores crop transform per selected platform preset; the crop icon only appears after a preset is selected, and export must read `payload.transforms[preset.id]` so each output keeps its own crop.
- Watermark removal API rule: automatic image watermark removal must call PicWish/佐糖 `/api/tasks/visual/external/watermark-remove` with the source image field named `file`; do not route it to masked object removal `/api/tasks/visual/watermark`, which requires a mask and fails with `mask image does not exist`.
- External website image drag rule: canvas drag-drop from external websites should parse image URLs from `text/html`, `text/uri-list`, `text/plain`, `DownloadURL`, Firefox URL types, image/link/meta/video poster/lazyload/srcset fields, then fetch remote images through the existing image proxy and store them as DataURL asset nodes; keep clipboard paste behavior separate.
- External drag browser quirk rule: some browsers expose only `Files` during `dragover` for external webpage image drags, so the canvas must still `preventDefault` and wait for `drop` to read `text/html`/URL payloads; otherwise the drop event never reaches ArtX.
- External page image proxy rule: `/api/images/proxy` should support dragged webpage URLs, not only direct image URLs; for Huaban `huaban.com/pins/:id`, resolve the image through `https://api.huaban.com/pins/:id`, and for generic pages parse common `og:image`, `twitter:image`, `image_src`, `img`, `srcset`, video poster, lazyload attributes, CSS `url(...)`, JSON/script image fields, and common image CDN URLs before failing.
- External drag broad format rule: when expanding third-party website drag support, read every string `DataTransferItem` on drop, not just standard `getData("text/html")`; parse escaped/protocol-relative/data-image URLs, prefer larger `srcset` candidates, and keep `/api/images/proxy` able to resolve HTML/JSON-LD/script image fields. Huaban pin API requires a trailing slash, `https://api.huaban.com/pins/:id/`, otherwise it can return 405.
- External drag Tencent/Huaban rule: Tencent News article URLs can resolve to extensionless `gtimg`/`qq.com`/`shiply-cdn.qq` image CDN candidates, while Huaban pin URLs need browser-like API headers and both trailing-slash/no-slash endpoint fallbacks; validate with `/api/images/proxy` returning a real image content type.
- External drag Zcool rule: Zcool work pages such as `zcool.com.cn/work/*.html` expose usable `og:image` and `img.zcool.cn/community` assets; paste should reuse the same rich HTML/plain-text extraction as drag-drop, and local validation should use a full backend server rather than pure Vite frontend.
- External drag local proxy rule: when testing webpage image drag locally on the full production server such as `localhost:5018`, image proxy requests must use the same local origin even if `VITE_API_BASE_URL` points to `https://artx-test.onrender.com`; otherwise newly fixed local proxy parsers are bypassed and drag-drop appears unchanged.
- External drag Chrome dedupe rule: Chrome can expose the same dragged webpage image as multiple `Files` entries while Safari may expose only one source; image preview pages may expose both a thumbnail and the original image. Dedupe URL-sourced drops by a dimension-independent visual fingerprint; for file-sourced drops that also include webpage string payloads, treat it as one external webpage drag and keep only the largest source pixel area before adding canvas nodes. Do not apply this one-image clamp to local Finder multi-file drops.
- External drag Chrome file-only dedupe rule: Chrome webpage image drags may arrive as multiple `Files` entries without `text/html`/URL string payloads; if the files are same-named image files or browser-generic image names, treat them as duplicate browser candidates and keep only the largest source pixel area.
- Visible asset source rule: image copy/paste, AI edit/generation, annotation edit, crop/rotate, multi-platform export, selected-image download, batch download, and artboard export should read the current visible asset source by baking `assetAdjustmentPreview` or `assetAdjustments` into a DataURL before passing it onward; this prevents brightness/highlight edits from reverting to the original bitmap.
- Visible asset baking rule: when a canvas image has visual adjustments, all downstream operations must consume the baked visible pixels, not the original `localSrc`; this includes bottom/right AI reference chips, image-generator references, cross-canvas copy/paste, external URL paste normalization, single download, batch download, artboard export, and PSD layer export. Remote images should be read through Blob/proxy fallback before baking to avoid CORS reverting to the original.
- Canvas keyboard copy/paste rule: Ctrl/Cmd+C for selected canvas nodes writes to ArtX's internal cross-canvas clipboard, and Ctrl/Cmd+V must prefer that internal clipboard before showing system-clipboard image errors; if visible-image baking is still pending, paste should wait for that pending copy task before inserting nodes.
- Canvas assistant composer rule: image/annotation reference chips must keep adjacent empty text insertion slots so users can click before or after a chip to type; composer placeholder text should show only when there are no chips and no user text, and composer scrolling should depend on content overflow after the user-adjustable input height.
- Canvas assistant inline composer rule: bottom-right prompt text and image/annotation chips must render as one inline token flow, not separate multi-line textarea blocks; text slots stay single-line, empty text slots must occupy 0px, typed text width should be computed during React render from measured text pixels plus padding so the first typed character remains visible, chips can be mixed between text fragments, automatic wrapping should use about 2px row gap, rows must stay flex-start aligned so line spacing does not change with composer height, and placeholder/default text must stay top-aligned after the composer is resized taller.
- Canvas assistant Backspace rule: when a mixed prompt text segment is backspaced down to zero characters, keep the text segment alive and focused so the user can continue typing there; do not let the browser remove the editable field or break the inline chip/text flow.
- Canvas assistant skill token rule: when a Skill is selected, the bottom-right mixed prompt input must show the active Skill as one blue inline token; deleting that token cancels `activeSkill`, so generation must not use the Skill again until the user selects it again.
- Canvas assistant prompt scrollbar rule: bottom-right mixed prompt input must never show a horizontal scrollbar when text and image/annotation chips wrap; keep horizontal overflow hidden, hide visible scrollbars on the prompt shell, and let text/chips wrap inside the available width.
- Canvas visual-node context menu rule: after a visual node is selected by left click, the floating toolbar must intercept right-click and open the same `NodeContextMenu` as right-clicking the node, preventing the browser/system context menu while preserving copy, paste, note, and delete actions.
