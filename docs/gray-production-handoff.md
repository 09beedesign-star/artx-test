# ArtX 灰度生产环境任务交接

## 目标

为 ArtX 创建或确认灰度生产环境，用于正式上线前验证正式域名、服务器、后端、支付、登录、AI 调用、MCP/API Key 等能力。

灰度环境不是普通测试环境，而是准生产环境。它应该尽量接近正式生产配置，但需要访问保护，避免被外部用户盗用 AI token 或消耗额度。

## 已知信息

- 正式域名：`www.artxsd.com`
- 云服务器系统：Debian 13.2 64bit
- 服务器公网 IP：`43.161.241.133`
- 灰度前端域名：`gray.artxsd.com`
- 前端部署位置：云服务器
- 后端状态：已部署在同一台云服务器上，但需要审计确认端口、进程方式、代理和环境变量
- 当前 ArtX 测试/灰度入口：`https://backstage.artxsd.com`
- 当前 ArtX 测试/灰度后端：`https://backstage.artxsd.com`
- 当前主测试分支：`test/feature/interaction-framework`

## 核心原则

1. 不要假设服务器是空的。先审计当前服务器状态，再补齐灰度环境缺口。
2. 不要直接发布到正式生产环境。先从测试环境发布到灰度环境，灰度稳定后再切正式发布。
3. AI token、支付密钥、Google OAuth secret、数据库密码等敏感信息绝不能暴露在前端或聊天内容里，只能放在后端环境变量或服务器安全配置中。
4. 灰度环境必须加访问保护，至少使用 Basic Auth、IP 白名单、账号白名单、邀请码或其他限制方式之一。
5. 未登录用户不得调用 AI 能力。AI 调用应走后端，并经过登录、额度、频率和积分扣减检查。
6. 前端和后端如果部署在同一域名下，优先考虑：
   - `gray.artxsd.com` 提供前端静态文件
   - `gray.artxsd.com/api` 反向代理到后端
   - `gray.artxsd.com/uploads` 反向代理或映射到后端上传文件
7. 如无必要，先不单独创建 `api-gray.artxsd.com`，减少跨域和 Cookie 配置复杂度。

## 需要先审计的问题

### 服务器权限

- 是否有 SSH 登录权限？
- 如果没有 SSH，是否有云服务商控制台远程终端、宝塔、1Panel、aaPanel 或其他面板权限？
- 最小需要能操作：文件上传、Nginx 配置、HTTPS 证书、服务重启、环境变量、日志查看。

### DNS

- `gray.artxsd.com` 是否已添加 A 记录？
- A 记录是否指向 `43.161.241.133`？
- DNS 是否已生效？

### 后端

- 后端是否已经部署在服务器上？
- 后端运行端口是多少？
- 后端运行方式是什么：pm2、Docker、systemd、Node 进程、面板托管或其他？
- 后端健康检查地址是什么？
- `/api` 是否可访问？
- `/uploads` 是否可访问生成图片？
- 后端环境变量是否齐全？
- AI token、支付密钥、Google OAuth、数据库地址是否只存在后端环境变量中？

### 前端

- 服务器上是否已有前端静态目录？
- 是否已有 `gray.artxsd.com` 站点配置？
- 如果没有，建议使用 `/var/www/artx-gray` 作为前端静态目录。
- 前端构建时 API 地址应指向灰度域名，例如同域 `/api` 或灰度后端地址。

### Nginx / 反向代理

- 是否安装 Nginx？
- 是否已有 `www.artxsd.com` 或 `gray.artxsd.com` 配置？
- 推荐结构：
  - `gray.artxsd.com/` -> 前端静态文件
  - `gray.artxsd.com/api/` -> 后端服务端口
  - `gray.artxsd.com/uploads/` -> 后端 uploads 或静态上传目录

### HTTPS

- 是否已有 certbot 或其他证书工具？
- `gray.artxsd.com` 是否已有 HTTPS 证书？
- 如果没有，需要申请证书并配置自动续期。

## 灰度环境安全保护

建议至少启用以下保护：

1. 灰度站点访问保护：Basic Auth、IP 白名单、邀请码或账号白名单。
2. 未登录用户禁止使用 AI 能力。
3. AI 调用必须后端鉴权，前端不能出现任何真实 token。
4. 单用户每日额度限制。
5. 单 IP 频率限制。
6. API Key 独立限额、可禁用、可重置、可审计。
7. 后台记录每次 AI 调用，包括用户、能力、模型、时间、状态、消耗。
8. 异常告警：高频调用、成本突增、支付异常、失败率异常。
9. 灰度环境优先使用低额度或灰度专用 AI token，不直接使用正式高额度 token。

## 推荐发布流程

1. 先确认当前主测试环境 `test/feature/interaction-framework` 已通过验证。
2. 从测试分支构建灰度发布版本。
3. 上传前端构建产物到服务器灰度静态目录。
4. 确认后端服务、环境变量和上传目录可用。
5. 配置 Nginx：
   - 前端静态文件
   - `/api` 反向代理
   - `/uploads` 映射或反向代理
   - 灰度访问保护
6. 配置 HTTPS。
7. 验证：
   - `https://gray.artxsd.com` 可打开
   - 登录状态正常
   - `/api` 正常
   - `/uploads` 图片可访问
   - AI 生成、Skill、抠图、去背景、橡皮擦、扩图、注释不回归
   - 支付二维码、支付回调、充值/订阅成功弹窗正常
   - Google 登录回调正常
   - MCP/API Key 可用且有限额
8. 记录部署版本和回滚点。
9. 灰度稳定后，再执行正式生产切换。

## 需要用户提供的信息

不要提供 token、密码、私钥原文。只需要提供：

- 是否能 SSH 登录服务器
- SSH 用户名和端口，密码或私钥不要发聊天
- 是否有服务器面板权限
- DNS 是否已添加 `gray.artxsd.com`
- 后端端口
- 后端运行方式
- Nginx 是否已安装
- HTTPS 证书工具是否已安装
- 环境变量是否已配置到服务器
- 是否启用 Basic Auth、IP 白名单、邀请码或账号白名单
